# Book_Agent 接口文档

> 维护约定：每完成一个开发步骤，将新模块接口追加到本文件；描述须与代码中 `@Tag`/`@Operation` 一致。

> 2026-10-15 阶段 1–3 已扩展个人账号、分享、版本、备份、采集和全库检索。新增接口及当前权限规则见 [阶段 1–3 接口与设计](阶段1-3接口与设计.md)。

## 通用约定

- Base URL：`http://localhost:8080`
- 统一响应外壳：`{ "code": 200, "message": "success", "data": ... }`；HTTP 状态码恒为 200，**业务成败看 code**
- code 约定：200 成功 / 400 参数错误 / 401 未登录 / 403 无权限 / 404 不存在 / 409 状态或版本冲突 / 429 繁忙 / 503 AI 不可用 / 500 失败
- 鉴权：除免登录名单外均需携带请求头 `Authorization: <tokenValue>`（登录接口发放）
- 个人业务接口要求有效登录并按所有权/分享范围校验；/api/admin/** 要求 ADMIN。认证 me/logout 要求有效登录。内部接口单独使用 `X-Internal-Token`，不接受管理员 token 替代。
- 免登录区：`/api/auth/login`、`/api/auth/register`、`/api/hello`、`/api/blog/**`、`/doc.html`、`/v3/api-docs/**`、`/swagger-ui/**`、`/error`
- 调试入口：doc.html（knife4j），Authorize 按钮填 tokenValue 全局生效

## 2. 旧文章兼容接口

文章与 Book 统一为 Book，推荐使用第 11 节的 /api/books。/api/articles 不再写 article 表，由 LegacyBookIds 统一呈现与解析兼容 ID。有 legacy_article_book 映射时，响应 id 是原 article ID；新 Book 无映射时，响应 id 是 2^52+bookId 的不透明数值句柄，bookId 为规范 ID，readerUrl 为 /books/{bookId}。句柄在 JavaScript 安全整数范围内，旧客户端须原样回传，不自行运算或当作规范 Book ID。

输入 id≥2^52 时解析为保留区句柄（bookId 必须大于 0 且小于 2^52）；普通 id 先查历史 article 映射，未映射才回退为 Book ID。因此同值历史 ID 的映射优先，不新增别名表。新客户端始终使用规范 Book 路径。兼容响应保留其他 Book 字段。

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | /api/articles | title/content/summary/categoryId/tagIds 创建 ONLINE Book 草稿，自动索引 |
| GET | /api/articles | 与 /api/books 相同筛选；列表各项使用兼容 id 并补充 bookId/readerUrl |
| GET | /api/articles/{id} | 映射后读取 Book 详情 |
| PUT | /api/articles/{id} | 用 ArticleSaveDTO 兼容保存，返回 Book；旧接口不提供客户端 revision 防护 |
| DELETE | /api/articles/{id} | 软删除映射后的 Book |
| PUT | /api/articles/{id}/publish | 发布 Book |
| PUT | /api/articles/{id}/offline | 下线 Book |

所有接口要求登录及相应 Book 权限。原 article 与 article_tag 保留为迁移档案，不再作为主产品读写来源。

## 7. 写作任务（@Tag：写作任务）— S6 / M2

| 方法 | 路径 | 功能 | 入参 | 返回值（data） |
|---|---|---|---|---|
| POST | `/api/tasks` | 创建写作或旧文润色任务 | Body：topic*（≤128 字）、instructions（≤2000 字）、sourceArticleId（可选） | 任务详情；新主题 OUTLINE，旧文 POLISH |
| GET | `/api/tasks` | 分页查询写作任务 | Query：pageNum（默认1）、pageSize（默认10，上限50） | `{total,pageNum,pageSize,list}`，列表不含正文结果 |
| GET | `/api/tasks/{id}` | 查询任务与当前检查点 | Path：id | `{id,topic,stage,status,output,approvedContent,articleId,bookId,resultBookId,error,runId,createdAt,updatedAt}（bookId 为可选知识源，resultBookId 为完成后的 Book）` |
| GET | `/api/tasks/{id}/checkpoints` | 查询人工确认历史 | Path：id | `{stage,generatedContent,approvedContent,createdAt}[]` |
| POST | `/api/tasks/{id}/review` | 确认当前阶段，最终结果另存为新 Book 草稿并索引 | Path：id；Body：runId*、content*（≤200000 字） | 更新后的任务详情 |
| POST | `/api/tasks/{id}/cancel` | 取消写作任务 | Path：id | 无 |
| POST | `/api/tasks/{id}/retry` | 重试失败阶段 | Path：id | 无 |
| DELETE | `/api/tasks/{id}` | 删除终态任务记录，保留已经保存的草稿 | Path：id；仅 COMPLETED/FAILED/CANCELLED | 无 |

阶段：`OUTLINE → DRAFT → POLISH`。状态：`QUEUED → RUNNING → WAITING_REVIEW`；确认后进入下一阶段，最后确认则 `COMPLETED` 并创建新 DRAFT Book，写入 task_book_result 并自动索引。生成异常进入 FAILED；retry 回到 QUEUED。取消后 CANCELLED，不继续推进。每次运行发放新 runId，前端确认必须携带当前值。

异常情况：任务不存在为 404；错误阶段、重复确认、过期版本、取消已完成任务、重试非失败任务、删除进行中任务为 409；校验失败为 400；无模型/服务不可达时任务状态 FAILED，error 为可读提示；ADMIN 鉴权为 401/403。

## 9. 遗留站内问答兼容接口（@Tag：站内问答）— M3

| 方法 | 路径 | 功能 | 入参 | 返回值（data） |
|---|---|---|---|---|
| POST | `/api/blog/ask` | 基于所选当前已发布 Book 回答 | Body：question*（≤500 字）、bookId 或兼容 articleId、history（最多6条）；免登录 | `{answer,sources,mode:"hybrid"}` |
| POST | `/api/ask` | 基于所选当前已发布 Book 回答 | Body：同上；登录 | 同上 |

QuestionController 优先使用 bookId；否则经 LegacyBookIds 解析 articleId。二者均未提供时返回“请先选择一本已发布的 Book，再针对内容提问。”、sources=[]、mode=hybrid。两条 Java 路径都调用 askPublished，即使 /api/ask 要求 ADMIN，也不能借此询问草稿/下线内容。它们不是 article 快照全站问答；新问答使用第 11/14 节规范 Book 接口。

## 11. Book 管理（所有者 / 授权）

文章与 Book 是同一概念。新建默认 DRAFT；发布后进入公开书库，草稿和下线仅所有者、被授权用户或系统管理员可访问。在线正文保存、文件型 Book 原文件替换均自动增加修订并排队索引。上传文件直接创建一本 Book，初始 revision=1。统一 Java Result 外壳，业务错误读取 code。

| 方法 | 路径 | 入参 | data |
|---|---|---|---|
| GET | /api/books | keyword/status/categoryId/tagId/pageNum/pageSize（最大50） | {list,total,pageNum,pageSize}；列表不含正文/附件 |
| POST | /api/books | 在线编写：title*≤128、summary≤500、content≤100万（可空草稿）、categoryId、tagIds（≤20） | Book详情，sourceMode=ONLINE |
| GET | /api/books/{id} | id | Book详情，含正文/附件 |
| PUT | /api/books/{id} | 同创建，revision*须匹配 | Book详情 |
| GET | /api/books/{id}/read | id | {book,sections}；原文阅读，文件型解析原文件 |
| PUT | /api/books/{id}/publish | id；DRAFT/OFFLINE | 发布后的 Book 详情 |
| PUT | /api/books/{id}/offline | id；PUBLISHED | 下线后的 Book 详情 |
| DELETE | /api/books/{id} | id | 无；软删除并排队清理 |
| POST | /api/books/upload | multipart file*；PDF/DOCX/TXT/MD，≤20MB；title选填（默认文件名去扩展名），summary/categoryId/tagIds选填 | 新Book详情，sourceMode=UPLOAD，revision=1，单一原文件 |
| POST | /api/books/{id}/file | multipart file*、revision*；仅文件型Book | 替换后Book详情；同内容不重复索引，旧原文件后台清理 |
| DELETE | /api/books/{id}/files/{fileId} | 仅旧版在线Book的历史附件兼容操作；文件型Book禁止单独移除原文件 | Book详情 |
| GET | /api/books/{id}/files/{fileId}/download | id/fileId | {url,expiresIn:120}，私有限时下载 |
| POST | /api/books/{id}/reindex | id | 无；增加版本并重建 |
| POST | /api/books/{id}/ask | question*≤500，topK=5（1–10），history（可选，最多6条） | {answer,sources,mode:"hybrid"} |

Book详情：id/title/summary/content/sourceMode/revision/indexedRevision/indexStatus/indexError/chunkCount/status/categoryId/categoryName/tags/viewCount/publishedAt/createdAt/updatedAt/files。sourceMode为ONLINE或UPLOAD。UPLOAD的content为空字符串，实际内容来自唯一原文件；不接受用非空content覆盖原文件。files为{id,originalName,extension,size,sha256,createdAt}[]。旧POST /api/books/{id}/files已取消，不再添加参考资料。索引状态 QUEUED/RUNNING/READY/FAILED；删除内部状态 DELETING/DELETED。READY且indexedRevision=revision才允许问答与知识写作。

sources：{citation,bookId,chunkId,sourceName,fileId,chunkNo,page,score,excerpt}[]。fileId=null代表正文，page=null表示没有页码；引用序号对应回答中的[1]等数字。

错误：401/403鉴权；400空标题/格式/文件头/大小/数量；404不存在或已删除；409版本冲突或索引未就绪；429问答并发繁忙；503模型或向量服务不可用。解析错误写入indexError，在页面重试。正文更新失败不覆盖当前内容。

## 12. Book 写作扩展

POST /api/tasks 支持 bookId，不能与 sourceArticleId 同时传入；知识源 Book 必须当前修订 READY。sourceArticleId 为旧润色兼容字段，映射到 Book 读取正文，直接进入 POLISH。所有任务（包括没有知识源的新主题）最终人工确认均创建新 ONLINE Book 草稿并自动排队索引，返回 resultBookId。bookId 为可选知识源；旧 articleId 字段只兼容历史任务。新 Book 不覆盖源内容或复制原文件，不自动发布。

## 14. 公开 Book 阅读（免登录）

| 方法 | 路径 | 入参 | data |
|---|---|---|---|
| GET | /api/blog/books | keyword/categoryId/tagId/pageNum/pageSize | Book分页，仅PUBLISHED，传入status不改变公开范围 |
| GET | /api/blog/books/{id} | id | 已发布Book详情 |
| GET | /api/blog/books/{id}/read | id | {book,sections}，阅读并原子增加浏览量 |
| POST | /api/blog/books/{id}/ask | question/topK/history，同ADMIN | 当前Book答案和来源，回答后再核验发布状态 |
| GET | /api/blog/books/{id}/files/{fileId}/download | id/fileId | {url,expiresIn:120}，核验发布后签名 |

不存在、删除、草稿、下线返回404；原文读取、问答或签名处理中的修订变化为409，问答未就绪也为409。BookService 按访问范围统一前后校验；公开接口在完成校验时必须仍为PUBLISHED，但同一修订先下线再发布的撤回历史无法识别。读原文不要求索引就绪，返回固定 BookReadVO（BookVO book、JsonNode sections 数组）。ONLINE 的 sections 为空，使用 book.content 净化渲染；UPLOAD 的 sections 为 {sourceName,fileId,page,text,format}[]，PDF保留页码，format=md时净化渲染。对象本身不授予匿名访问；已发放的120秒签名不能即时撤销。

history 为 {role,content}[]，最多6条；role 仅 user/assistant，content 必填且≤4000字。历史用于追问上下文，当前Book检索原文仍为回答依据。发布状态DRAFT→PUBLISHED⇄OFFLINE，publishedAt只记录首次发布，viewCount不改变内容updatedAt。发布、索引与修订状态分别管理；文件型Book发布前要求当前修订索引就绪。

问答 answer 统一为 Markdown 的“结论”和“论据”两部分，公开 Book、后台 Book 及遗留站内问答均采用此结构。结论直接回答；论据只保留校验后的出处编号，供前台显示 Book / 文件名与页码链接。同一文件的同一页合并，不解释或摘录。没有相关片段时不调用聊天模型，返回两部分的依据不足说明，sources=[]；不能据此声称整个知识库没有该主题。模型输出由 AI 服务校验非空结论/论据与引用编号，格式错误最多重试一次，再失败返回503，不伪造出处。写作提纲、扩写和润色不受此问答格式约束。

接口边界与兼容方案的取舍见 [架构评估与优化 RFC](架构评估与优化RFC.md)。

## 15. 笔记助手与 Agent（阶段 4）

这些接口要求当前用户登录。Book 操作按 `KnowledgeAccess` 校验读取/编辑权限；计划、偏好、建议与草稿均按当前用户隔离。模型生成只产生预览，只有 `/apply` 或 `/drafts` 等明确确认操作才会写入 Book。

### Book 笔记助手

| 方法 | 路径 | 功能 | 入参 | 返回值（data） |
|---|---|---|---|---|
| POST | `/api/books/{id}/assistant` | 生成笔记建议或执行知识检查 | Body：`operation` 为 `organize/polish/review/explain/related/duplicates`；可选 `instructions`≤2000、`level`≤40、`bookIds`≤100 | 建议对象、检查发现与来源，或相关检索结果；附当前 `revision` |
| POST | `/api/books/{id}/assistant/apply` | 作者确认应用整理/润色结果 | Body：`expectedRevision`、`operation`=`organize/polish`，以及 title/summary/content/category/tags | 更新后的 Book；增加修订并按 Book 保存流程更新索引 |

`organize` 仅更改元数据；`polish` 仅用于在线正文。应用时必须匹配 `expectedRevision`；过期时返回 409。文件型 Book 不允许应用正文润色。`review` 只返回具有检索来源的重复/冲突/核验发现；`explain` 解释当前 Book 支持的内容；`related` 与 `duplicates` 返回其他已授权 Book 的检索证据。AI 不会自行应用建议或发布 Book。

### 个人偏好、计划与合并草稿

| 方法 | 路径 | 功能 | 入参 | 返回值（data） |
|---|---|---|---|---|
| GET / PUT | `/api/assistant/memory` | 读取/保存当前用户长期偏好 | PUT Body：`preferences`≤4000 | 字符串 / 无 |
| GET | `/api/assistant/recommendations` | 根据当前用户 Book 元数据与索引状态返回整理建议 | 无 | `{bookId,title,kind,message}[]` |
| POST | `/api/assistant/plans` | 自动生成或保存自定义 Agent 计划 | Body：`goal`≤1000、`bookIds` 1–50 本已就绪且可访问的 Book；可选 `steps` 1–6 项，每项含 `tool`、`title`≤100、`instruction`≤500 | 计划、范围与步骤 |
| GET | `/api/assistant/plans` | 列出当前用户最近 30 个计划 | 无 | 计划摘要数组 |
| GET | `/api/assistant/plans/{id}` | 读取计划、状态与步骤结果 | Path：计划 ID | 计划详情 |
| PUT | `/api/assistant/plans/{id}/steps/{stepId}` | 修改步骤类型/名称/要求，并重置本步骤及后续步骤结果 | Body：可选 `tool`、`title`≤100、必填 `instruction`≤500；前序成功结果保留 | 更新后的计划与步骤 |
| POST | `/api/assistant/plans/{id}/steps` | 在指定步骤后插入步骤；不传 `afterStepId` 时追加到末尾 | Body：`tool`、`title`≤100、`instruction`≤500、可选 `afterStepId`；每个计划最多 6 步 | 更新后的计划与步骤 |
| PUT | `/api/assistant/plans/{id}/steps/{stepId}/position` | 调整步骤顺序，并重置受影响步骤及后续结果 | Body：`position` 1–6 | 更新后的计划与步骤 |
| DELETE | `/api/assistant/plans/{id}/steps/{stepId}` | 移除步骤，并重置受影响的后续结果 | Path：计划与步骤 ID；每个计划至少保留一步 | 更新后的计划与步骤 |
| POST | `/api/assistant/plans/{id}/steps/{stepId}/reset` | 从指定步骤起清除旧结果，保留更早步骤的结果供重跑 | Path：计划与步骤 ID | 更新后的计划与步骤 |
| POST | `/api/assistant/plans/{id}/steps/{stepId}/run` | 手动执行一个计划步骤 | Path：计划与步骤 ID | 更新后的步骤和结果 |
| DELETE | `/api/assistant/plans/{id}` | 删除非执行中的计划与步骤 | Path：计划 ID | 无；已另存的 Book 草稿保留 |
| POST | `/api/assistant/merge/preview` | 基于 2–10 本可访问 Book 生成带来源合并预览 | Body：`title`≤128、`instructions`≤1000、`bookIds` | `{content,sources}` |
| POST | `/api/assistant/drafts` | 经用户确认把起草结果另存为私有 Book | Body：`title`、`summary`、`content`≤100万字符、`sourceBookIds` 1–50 | 新 DRAFT Book，自动建立索引 |

计划可由 AI 自动生成，也可在创建前由用户手动排列 1–6 个步骤。保存后可编辑、插入、移动和移除步骤。工具白名单为 `search`、`summarize`、`compare`、`draft`、`proofread`；总结、比较、起草和校对前必须有检索，校对前还必须有起草。只有 `search` 发起 RAG；其余工具只处理前序检索片段与生成内容，没有可用来源时返回明确错误，不把处理指令当成新检索问题。步骤必须按顺序执行；结构或要求变更会清除受影响步骤及后续的旧结果，保留更早的结果供重跑。发现“已有检索来源但下游回答未检索到出处”的旧结果时，界面提供从该步起重跑的操作。每步执行前后重新核对权限与 Book 修订；成功结果持久保存，失败可重试。偏好只作为表达参考，不改变来源证据。合并预览不修改来源 Book；另存结果为新的私有 Book，不自动发布。

### AI 内部笔记接口

| 方法 | 路径 | 功能 | 入参 | 返回值 |
|---|---|---|---|---|
| POST | `/internal/assistant` | 执行受限笔记/计划生成 | Header：`X-Internal-Token`；Body：operation、title/content/goal/instructions/level/memory/book_titles/sources | 结构化建议、步骤、发现或 `{content,sources}` |

仅支持 `organize`、`polish`、`review`、`explain`、`merge`、`plan`、`summarize`、`compare`、`compose`、`proofread`、`learning_roadmap`、`learning_report`。`summarize`、`compare`、`compose`、`learning_roadmap` 必须接收已检索的来源片段；`proofread` 还必须接收前序草稿。结果保留服务端传入的来源链接。来源片段、Book 正文和长期偏好均按不可信材料处理；缺少来源或格式错误时返回错误，不伪造来源。无公共匿名模型调用端点。

## 16. 学习辅助 Agent（阶段 6）

这些接口要求当前用户登录。学习范围仅能选择有权访问且当前索引就绪的 Book；计划、学习任务、打卡和报告均按当前用户隔离。

| 方法 | 路径 | 功能 | 入参 | 返回值（data） |
|---|---|---|---|---|
| POST | `/api/learning/plans` | 从目标和 Book 证据生成学习路线 | `goal`≤1000、`bookIds` 1–50、`currentLevel`、`selfConfidence` 1–5、`durationWeeks` 1–8、`sessionsPerWeek` 1–7、`minutesPerSession` 10–180，可选 `startDate` 与 `knownTopics`≤1000 | 路线、逐周任务、日期、来源、进度与薄弱点 |
| GET | `/api/learning/plans` | 列出当前用户学习路线及进度 | 无 | 路线摘要数组 |
| GET | `/api/learning/plans/{id}` | 获取路线、周目标、任务、打卡、来源与报告 | Path：路线 ID | 路线详情 |
| PUT | `/api/learning/plans/{id}/sessions/{sessionId}` | 保存任务打卡、掌握度和反思 | `status`=`PLANNED/COMPLETED/NEEDS_REVIEW/SKIPPED`、可选 `confidence` 1–5、`reflection`≤2000；完成或待复习必须填写掌握度 | 更新后的路线与进度 |
| POST | `/api/learning/plans/{id}/report` | 基于已完成学习记录生成阶段报告 | Path：路线 ID；至少有一条已完成/待复习记录 | 总结、水平估计、优势、薄弱点、下一步和来源 |
| DELETE | `/api/learning/plans/{id}` | 删除路线及其学习任务 | Path：路线 ID | 无 |

掌握度和水平来自用户自评、打卡状态与反思；报告中的水平为估计，不是正式考试结果。修改学习记录会使已保存报告失效。报告只引用计划创建时已检索且生成报告时仍有权访问的 Book 来源；Book 权限或 revision 改变时返回 409。运行时以幂等 DDL 创建 `learning_plan` 与 `learning_session`，不会清空既有记录。页面入口：登录后打开 `/admin/learning`。

## 17. 统一知识范围目录与公开跨 Book 问答

| 方法 | 路径 | 功能 | 鉴权 / 入参 | 返回值（data） |
|---|---|---|---|---|
| GET | `/api/knowledge/catalogue` | 我的知识范围候选目录 | 需要登录，按既有 Book 权限过滤 | `{books,categories}` |
| GET | `/api/blog/knowledge/catalogue` | 公开书库范围候选目录 | 匿名可用，仅已发布 Book | `{books,categories}` |
| POST | `/api/blog/knowledge/ask` | 公开跨 Book 问答 | 匿名可用，必须显式提交非空 `bookIds`；服务端强制公开范围 | 与 `/api/knowledge/ask` 一致的回答及真实来源 |

目录不返回正文。`books` 每项包含 `id`、`title`、`categoryId`、`sourceMode`、`revision`、`indexedRevision`、`indexStatus`；`categories` 每项包含 `id`、`name`、`parentId`。公开目录只返回所列 Book 使用的分类及祖先；私人目录还包含当前用户可见的分类。共享 Book 的所属分类祖先可用于展示，不返回无关私人分类。最多 5000 本，超过上限返回业务 code=400，不静默截断。未就绪条目供界面展示状态，不能用于执行问答。

分类勾选由前端解析为明确的 `bookIds`，原有检索、会话、Agent、合并、关联检查和学习接口继续使用 Book ID 集合与原权限 / 修订校验，不接收未授权分类通配符。

公开问答请求字段：`question` 必填、最多 500 字；`bookIds` 必填且非空、最多 5000 项，元素为正整数；可选 `searchMode`=`hybrid/semantic/keyword/fulltext`、`mode`=`qa/summary/compare`、`topK`=1–30、`rerank`、`history`（最多 20 条历史消息）。客户端传入 `publicOnly:false` 也不能绕过公开限制。未选 Book 返回业务 code=400，任一 Book 私有、下线、索引未就绪或处理期间状态 / 修订改变时返回 code=409，检索并发容量不足返回 code=429。遵循现有 Result 包装的业务码约定。

登录后的阅读页多 Book 问答复用 `/api/conversations` 和消息接口以持久化会话；匿名多 Book 问答使用本节公开端点。当前 Book 的默认问答接口保留。界面、选择数量限制和验收步骤见[知识范围选择与验收](知识范围选择与验收.md)。

## 18. 上下文管理增量

`POST /api/conversations/{id}/messages` 自动组织近期消息、相关旧用户问题和服务端派生意图摘要。请求仍只接收 `question`；调用方不能提交或覆盖服务端摘要。响应可附 `context` 数值 / 布尔诊断：`historyTotal`、`historyUsed`、`historyRecalled`、`summaryUsed`、`evidenceTokens`、`summaryCoveredMessageId`、`summaryUpdated`、`summaryFallback`。这些不是计费 Token 总数；实际模型 usage 只在服务商提供时记入脱敏日志。

摘要按会话隔离，存入 `knowledge_conversation_memory`，字段为 `conversation_id`、`covered_message_id`、`memory_json`、`basis_hash`。会话删除时级联删除；备份 Book 的既有接口仍不包含聊天及其派生摘要。

内部 `POST /internal/context/compact` 要求 `X-Internal-Token`，接收 `previous` 结构化摘要和 `messages`，返回 `{memory}`；仅提取用户意图，摘要不是知识证据。内部 `/internal/knowledge/ask` 增加可选 `memory`，内部历史允许最多 1000 条供选择器从中提取相关旧问题；外部检索 / 问答 DTO 的历史上限仍为 20 条，不能借此写入摘要。`MEMORY` 与 `REWRITE` 模型任务复用配置中的 ASK 渠道，分别限制输出长度。

内部 `/internal/assistant` 增加 `step_memory`（最多 6 项，含 tool/title/instruction/output/findings），用于保留不同前序步骤；有效原文来源仍单独通过 sources 提供。长文分析采用明确标记的选段，润色和校对按完整输入分段；任何片段失败均不返回完整成功。流程、预算配置和验收见[上下文管理与验收](上下文管理与验收.md)。
