## 2. 发现和修复的问题

| 问题 | 实际影响 / 复现证据 | 修复 | 复验 |
|---|---|---|---|
| 真实 MySQL 创建学习路线返回 500 | H2 测试通过，但真实接口报“学习记录未生成 ID”；MySQL 默认自增列标签是 GENERATED_KEY | 明确请求 id 主键列，使用 GeneratedKeyHolder 标准取值，兼容 MySQL 与 H2 | 真实生成两条路线、保存任务与报告成功；Java 学习模块通过 |
| 报告生成期间学习记录变化，旧报告仍可保存 | 新增回归先复现：模型基于低分记录生成报告时，记录改为高分，旧报告仍返回 200 | 模型调用放在事务外；保存时锁定所属路线，再比较完整学习记录快照；有变化返回 409 | 新增后端回归由失败转为通过；旧报告不写入 |
| 待学习 / 已跳过任务仍被计为薄弱点 | 低评分任务恢复待学习后，薄弱点数量仍为 1 | 薄弱点只计算“需要复习”以及“已完成且低分”的记录，并统一进度 / 报告统计口径 | 新增后端回归覆盖恢复待学习和跳过 |
| 快速切换路线或保存期间切换，会被旧响应覆盖 | 学习页面没有区分请求对应的当前选择 | 记录选择代次；只有仍对应当前页面的读取、打卡、报告结果才能更新详情；增加读取中提示 | 新增前端乱序响应与保存期间切换测试；真实浏览器快速切换通过 |
| “需要复习”记录无法从页面生成报告 | 后端允许已学习但待复习的记录生成报告，前端却只按完成次数启用按钮 | 根据 COMPLETED / NEEDS_REVIEW 记录统一启用条件；保存中禁用报告按钮 | 新增前端回归；真实页面完成“待复习 → 报告”流程 |
| 手机日期框撑宽学习页面 | 390px 视口实测页面 scrollWidth 为 421px；组件默认日期宽度 220px 溢出网格 | 限定网格子项最小宽度，覆盖日期组件固定宽度，允许星级文字换行 | 修复后全部工作区 390px 遍历通过，无页面横向溢出 |
| 404 页面仍称“博客” | 与统一 Book / 书库用语不一致 | 调整为“回到书库”“返回书库” | 浏览器 404 页面和返回入口检查通过 |

本轮没有进行框架迁移、库结构重写或没有证据支持的性能改造。主要优化集中在真实运行兼容性、异步状态一致性、学习统计准确性和手机可用性。

## 4. 响应时间观察

在本机通过前端代理连续读取 Book 列表 20 次：P50 **8.31ms**、P95 **8.64ms**。这是顺序读取的小样本观察，不能代表高并发容量或生产 SLA，也没有据此声明百分比性能提升。

真实单 Book 回答的一个样本约 1.66 秒；跨文档总结与对比两次合计约 9.16 秒；四步 Agent 约 20.14 秒；完整三阶段写作含后台轮询约 27.49 秒。不同任务字数和内容不同，这些数字仅供本地演示时预期等待时间参考。

## 5. 可重复执行的测试入口

新增 `scripts/Test-Project.ps1` 与 `scripts/verify_ai.py`，复用现有 Java 21 / Maven / Node / WSL Python 环境，日志写到系统临时目录，不重启业务服务或修改应用配置。

```powershell
cd D:\Book_Agent
powershell -ExecutionPolicy Bypass -File scripts/Test-Project.ps1 -WithVectorDatabase
```

执行 Java 测试及 JAR 打包、AI 全量测试、前端测试和生产构建。`-WithVectorDatabase` 优先使用 `TEST_PGVECTOR_DSN`，否则读取项目 `.env` 的 `PGVECTOR_DSN`，不会输出密钥。向量库测试只使用独立测试表 / 测试 ID 并清理自身数据。

不带该开关时不会主动加载项目数据库配置；若调用环境也没有设置 `TEST_PGVECTOR_DSN`，6 项可选向量库测试会跳过。脚本需要已经安装依赖；不会自动安装服务或启动容器。

真实模型的业务验收与这条确定性测试命令分开：脚本不自动创建真实用户、不产生收费模型请求、不执行公网导入。
