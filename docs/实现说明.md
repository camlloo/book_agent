## 本轮架构收敛

- LegacyBookIds 统一旧接口的 ID 空间：历史映射返回原 article ID，无映射新 Book 返回 2^52+bookId 的不透明精确数值句柄，同时提供 bookId/readerUrl。原始历史 ID 映射优先，规范接口仍使用 Book ID；没有新增别名表或改写历史档案。
- BookService 统一 ADMIN/PUBLISHED 访问范围与修订快照，读取、问答、签名下载在处理前后复核；BookReadVO 固定读取响应结构，问答另校验索引就绪。
- readerSession 捕获请求目标 ID，按读取、目录及会话代次丢弃迟到结果；认证失效清理私有原文、目录与会话，保留公开内容。旧 token 的迟到 401 只有仍匹配当前 token 才触发注销，不会清除新登录。
- EmbeddingSpace 按 Provider 实际生效 URL、模型、维度共享空间身份，保持既有 Book 哈希命名。Book search 的模型等待置于事务外，状态、向量与关键词候选来自同一 REPEATABLE READ 只读快照。
- /internal/write 的 book_id/book_revision 成对校验，单边缺失422，索引修订冲突409。Java /api/blog/ask 与 /api/ask 都由 QuestionController 限定所选当前已发布 Book；仅内部 /internal/ask 接收显式文章快照。

## 边界

AI 无发布权限，已发布状态由作者控制；下线拒绝新的公开请求。公开读取、问答和下载签名在完成校验时要求仍 PUBLISHED，修订变化则拒绝，但同一修订中先下线再发布的撤回历史无法识别；已经签发的120秒 MinIO链接不能即时撤销。公开问答仅检索所选 Book 的就绪修订。删除业务访问立即失效，底层向量和对象异步清理。

正文100万字符、单文件20MB、解析200万字符、PDF1000页、Book10000分块，DOCX有条目和解压限制。扫描 PDF 需先 OCR，加密/损坏明确失败。未进行公网部署、非 Chrome 浏览器验证或本地嵌入模型完整质量评测。此前验收的两本临时 Book、临时分类、原文件与向量已清理，截图保留为历史证据；当时清理后再次核验原有15条档案和映射一致，不代表本轮清理核验已完成。

## 2026-10-18 阶段 4：笔记与 Agent

- `AssistantService` 协调 Book 助手、用户偏好、知识范围校验、计划持久化与逐步执行；MySQL 新增 `assistant_memory`、`assistant_plan`、`assistant_plan_step`。
- FastAPI `assistant.py` 只提供有界的结构化生成与白名单计划步骤；输入正文、检索来源和偏好按不可信资料处理。检索与业务授权仍由 Java 完成，模型没有数据库、文件系统或发布工具。
- 在线 Book 的元数据整理与正文润色先显示预览；应用时要求原修订号一致，走既有 Book 更新、版本历史和索引队列。文件型 Book 可建议元数据，不能直接改写上传原文件。
- 重复/冲突检查需要来自其他可访问 Book 的检索片段，发现必须包含有效来源编号；没有证据时不输出结论。关联知识和合并预览使用用户限定的检索范围。
- Agent 计划最多 6 步，只开放 search/summarize/compare/draft；步骤需用户逐个执行，每次前后复核 Book 权限与修订。结果持久化，失败步骤可重试。
- 合并和 Agent 起草只产生草稿预览；用户确认后另存为新私有 Book，并进入索引队列。原始 Book 不被覆盖，内容不会自动发布。
- 长期偏好按用户 ID 独立保存；主动建议由个人 Book 的简介、分类/标签和索引状态规则计算，不依赖外部推送。

## 2026-10-21 阶段 6：学习辅助 Agent

- 新增 `/admin/learning` 学习中心。用户选择授权且索引就绪的 Book，以目标、当前水平自评、学习周期、每周次数、单次时长和开始日期生成逐周路线与带来源的学习任务。
- `LearningService` 通过限定 Book 范围的混合检索取证，再要求模型返回严格周数/任务数的结构化路线；Java 校验结构和来源序号，只保留对应真实检索出处。
- 新增 `learning_plan` 与 `learning_session`，通过用户 ID 外键隔离存储计划、任务、日期、来源、自评、反思和报告。`LearningSchema` 在已有数据库中幂等建表，不删除现有数据。
- 用户可打卡、恢复或跳过任务，记录 1–5 分掌握度与反思；进度和低信心薄弱点即时计算，学习记录改变后会清除旧报告。
- 学习报告依据用户自评、任务记录、反思和来源片段生成；结果包括学习总结、估计水平、优势、薄弱点与下一步建议。报告明确不是正式考试，也不写回 Book。

本阶段全量复测：Java 32 项通过；Python 61 项通过、6 项可选 pgvector 测试跳过；前端 26 项通过，Vite 生产构建成功。学习模块新增 Java 集成测试 2 项、AI 结构测试 3 项。应用内浏览器未登录时管理路由正确跳转到登录页，未使用账户凭据进入管理空间；登录后的路线创建与打卡流程尚待用户在已登录会话中演示验收。详情见[阶段 6 学习辅助与验收](阶段6学习辅助与验收.md)。
