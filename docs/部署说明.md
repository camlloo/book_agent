# 部署说明

## 本机与已有基础设施

使用 README 的三个启动脚本。数据库初始化仅新增缺少的表；现有 MySQL、MinIO 与 pgvector 容器保持不变。确保数据库 `book_agent` 和用户已存在；第一次部署到新机器时，由有权限的数据库账号创建库和应用用户，再运行服务自动建表。

## 构建

1. `backend` 内执行 `mvn package`，使用 `java -jar target/backend-0.0.1-SNAPSHOT.jar` 运行。
2. `frontend` 内执行 `npm ci` 和 `npm run build`，将 `dist` 放到静态文件目录。
3. `ai` 内执行 `uv sync --locked`，使用安装环境运行 `uvicorn app.main:app --host 127.0.0.1 --port 8100`。Linux 服务环境通过环境文件加载必要配置；`.env` 不自动被裸 uvicorn 加载，本机脚本 `scripts/run_ai.py` 会加载。

参考 `deploy/nginx.conf` 配置同源 `/api` 代理和 Vue History 路由回退。文件是审查模板，没有修改当前机器的 Nginx 容器。按实际域名和目录调整模板；在公网使用 HTTPS。

## 配置边界

- Java 与 AI 的 `INTERNAL_TOKEN` 必须相同且非空；AI 的监听地址仅限内部网络。Nginx 不转发 `/internal/**`。
- `.env.example` 中数据库和存储值是开发默认值；在目标环境替换。已存在管理员不会随 `ADMIN_PASSWORD` 改动重置，需在数据库中用 BCrypt 管理密码或通过单独的管理员维护流程更新。
- `MINIO_PUBLIC_URL` 必须是访客能访问的 HTTPS 地址；否则浏览器无法加载图片或会发生 mixed content。可将独立图片域名反代至 MinIO。
- MinIO bucket 只对 `images/*` 开放匿名 GET，其余路径保持私有。
- 前端默认同源请求 `/api`；跨域部署可以在构建时设置 `VITE_API_BASE`，同时由部署层配置正确的 CORS。推荐使用同源代理。
- 生产运行 Java、AI 时使用服务管理器维护进程，不使用 Vite 开发服务器对外提供页面。
- 备份 MySQL、MinIO 对象和模型配置；任务/检查点以 MySQL 为准，向量数据可从 Book 正文与原文件重建。

## 验收

健康检查、登录、Book 草稿保存、发布、匿名正文与图片读取、下线后不可读、写作每阶段确认、最终新草稿、带引用的问答。真实生成验收需要可用模型渠道，真实语义质量验收需要可用中文 embedding 服务。

## Book RAG 部署补充

先运行Setup-RAG.ps1为已有pgvector容器创建独立数据库、应用账号和扩展，或由数据库管理员预建vector扩展并提供PGVECTOR_DSN。应用账号需要建表与HNSW索引权限，不要求超级用户。MySQL新增Book相关表由schema.sql追加创建。

Windows设置用户变量DASHSCOPE_API_KEY，Start-AI.ps1读取最新值并经WSLENV传递。默认聊天qwen3.8-flash，默认remote嵌入text-embedding-v4/1024维。Linux向AI服务注入相同变量与根.env配置；不要把密钥加入前端环境。可选本地嵌入首次下载需网络与CPU资源。

MinIO的books/保持私有。MINIO_ENDPOINT生成的签名链接必须同时对AI服务和有权阅读的浏览器可达；无法直接修改签名URL的主机名，域名/代理应在签名前配置正确。MINIO_PUBLIC_URL仅用于公开图片。生产应使用HTTPS可达域名，不能把127.0.0.1签名链接发送给远程浏览器。

Java限制单文件20MB、multipart请求21MB；Nginx模板client_max_body_size已改为101m。后台独立索引执行器、AI索引信号量1、问答信号量2，适用于当前单实例。删除对象每30秒清理，向量删除失败60秒重试；监控FAILED任务和长时间未purged附件。备份Book元数据与原始资料，恢复后重新索引即可重建向量。

新增验收：保存手写正文→索引就绪→引用问答；四种文件各自直接创建Book→MinIO私有→解析索引→页码/来源；在线正文修改与Book文件替换后旧内容不被检索；删除Book后向量和对象最终清理；知识写作三个阶段确认→新Book自动索引。扫描PDF需先OCR。

book_source以新增表记录来源模式，启动自动建表，无需ALTER原表或重写现有数据。文件型Book只接受一个≤20MB原文件，不再支持添加参考附件。

## 统一 Book 迁移与前台

BookMigration 在 Java 启动时幂等导入旧文章。新增 book_publication、book_tag、legacy_article_book、task_book_result；保留旧表，避免手工重复导入。原有 15 条记录已验证正文、发布状态、分类与标签一致。迁移后首次启动会对导入内容排队向量化，应观察索引失败状态并配置好嵌入服务。

公开 /api/blog/books 只返回 PUBLISHED；完整书库和编辑 /api/books 要求登录并按所有权/分享范围校验。MinIO books/ 不授予匿名 GET，发布的文件由公开接口验证后发放两分钟链接，下线无法立即撤销已发签名。必须配置签名地址供访客访问。阅读原文通过 Python /internal/books/read 按独立并发容量解析，不拼接有重叠的向量片段。

前端入口为 /、/books/:id、/books、/admin/books；旧 /articles/:id 解析到 Book，旧管理入口重定向。验收包含桌面双侧独立收缩、手机抽屉与焦点约束、直接 /ask、原文件按页阅读、匿名发布/下线和两轮引用对话。


## 阶段 1–3 部署补充

数据库启动追加所有权、分享、版本、来源、采集及对话表。旧 Book 归入已有管理员空间，旧内容不改写。备份应同时包含 MySQL 与 MinIO，pgvector 可从内容重建；应用内 ZIP 备份支持个人内容与历史原文件的迁移恢复，不包含账号密码和密钥。

Nginx 与 Spring multipart 允许100MB备份（请求上限101MB），Book原文件仍由业务层限制20MB。Python新增beautifulsoup4与reportlab，运行Start-AI会按uv.lock同步。采集只访问公网80/443，私有仓库令牌由GITHUB_TOKEN/GITLAB_TOKEN环境变量提供，Web源需要能直接返回正文。全文索引使用pgvector所在PostgreSQL追加tsvector/GIN，保持同一专用数据库，不需要新增Elasticsearch实例。

当前调度面向单实例。完整参数、访问保证和限制见[阶段1–3接口与设计](阶段1-3接口与设计.md)。
