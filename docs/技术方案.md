## 系统组成

| 层 | 技术 | 职责 |
|---|---|---|
| 前端 | Vue 3、Vite、Element Plus、Pinia | 公开阅读、管理、Markdown 编写与净化预览、检查点、问答 |
| 业务后端 | Java 21、Spring Boot 3.5.6、MyBatis Plus、Sa-Token | 用户鉴权、Book、文件元数据、任务和版本的唯一事实来源 |
| AI 服务 | Python 3.12、FastAPI、LlamaIndex | 文件解析、重叠切片、嵌入、混合检索、模型写作与问答 |
| 关系数据 | MySQL 8 | 用户、旧文章档案、分类/标签、任务/检查点、Book/原文件/索引任务、用户偏好、Agent 计划及学习路线/打卡 |
| 对象存储 | MinIO | images/ 公开图片；books/ 私有原始资料 |
| 向量数据 | PostgreSQL + pgvector | 持久化分块、来源元数据、版本注册、HNSW 与删除墓碑 |

前端调用 Java 同源 /api。Java 调用内部 Python 服务，二者使用相同的非空 INTERNAL_TOKEN。Python 不开放公共模型接口；AI 无发布权限，不直接修改 Book 或作者确认内容。

## 统一 Book 业务

管理员管理在线 Markdown 或文件型 Book、分类树和标签。状态为 DRAFT/PUBLISHED/OFFLINE；公开接口固定只读当前已发布 Book。浏览量原子递增，首次发布时间保留。分类父子循环与被引用分类删除均校验。图片限制 5MB，检查扩展名与文件头，使用 images/ 前缀。

写作任务按 OUTLINE → DRAFT → POLISH 推进，各阶段持久化作者确认的检查点。旧 Book 润色直接进入 POLISH，最终另存新草稿。每次执行分配 runId，回调与确认以当前状态和 runId 条件更新；取消或过期回调不能覆盖终态。终态任务可删除，但已保存作品保留。

三栏阅读统一调用 Book API。BookService 用 ADMIN/PUBLISHED 访问范围与修订快照统一读取、问答、下载签名的前后校验；原文响应固定为 BookReadVO（BookVO book、JsonNode sections，sections 必须为数组）。公开问答还要求完成时当前索引仍就绪。公开语义是完成校验时仍 PUBLISHED，不记录同一修订先下线再发布的撤回历史；已有 120 秒签名不能即时撤销。

Java 遗留 /api/blog/ask 与 /api/ask 由 QuestionController 按 bookId 或 articleId 限定当前已发布 Book；articleId 通过统一兼容 ID 解析，bookId 优先。没有选择 Book 时返回选择提示。仅 Python 内部 /internal/ask 保留显式文章快照兼容能力，不能描述成当前 Java 的全站 article 问答。

LegacyBookIds 拥有旧 ID 空间：历史映射返回原 article ID；无历史映射的新 Book 在旧接口返回 2^52+bookId，并补充 bookId/readerUrl。句柄不透明、在 JavaScript 安全整数范围内；保留原始历史 ID 映射优先，未映射普通 ID 保留 Book 回退兼容。规范 API 始终使用 Book ID，不新增别名表。历史文章 URL 通过映射跳转到 Book。

readerSession 捕获异步操作的目标 ID，读取与目录分别使用代次，会话代次使认证失效前的操作失效。原文、目录、章节收集、下载和回答避免乱序污染；切换 Book 的回答仍归属发起时的会话。认证失效清理私有原文/目录/会话，保留公开内容；api 只在 401 对应的请求 token 仍为当前 token 时注销，防止旧请求注销新登录。

## Book 数据与版本

新增 book、book_file、book_index_job、task_book、book_source、book_publication、book_tag、legacy_article_book、task_book_result 表。book_publication 独立保存状态、分类、浏览量与首次发布时间；book_tag 为标签关系；task_book_result 保证所有最终确认任务保存为 Book。BookMigration 启动时事务性、幂等地复制旧文章，并排队索引，原 article 表内容不改写。book_source标明ONLINE/UPLOAD；新增在线稿为ONLINE，上传原文件直接创建UPLOAD。旧记录缺省为ONLINE，历史文件不删除。DDL 在 backend/src/main/resources/db/schema.sql 中，启动仅创建缺失表，不清空已有数据；task_book 在 task 与 book 建表后创建。

book 保存正文和 revision/indexed_revision/index_status/index_error/chunk_count。新 Book revision=1，保存正文、修改标题/简介、替换原文件、重新索引时增加版本。更新必须携带匹配 revision；未发生修改不重复入队。MySQL 行锁保护附件去重、数量和修订生成。

book_file 保存原名、扩展名、私有 object_key、大小、SHA-256 与删除/清理标记。相同内容在同一 Book 活跃附件内去重。上传事务回滚会清理新对象。book_index_job 与正文变更同事务写入，(book_id,revision) 唯一；未执行的旧任务标记 SUPERSEDED。

## RAG 入库流程

1. 管理员在线保存 Book 正文，或上传一份 PDF/DOCX/TXT/MD（≤20MB）直接创建文件型 Book。上传型 Book 的原文件就是内容，正文为空；替换文件与业务修订在同一事务更新。MinIO 对象位于 books/{bookId}/{uuid}.{ext}，不授予匿名读取。
2. 独立单线程执行器每 2 秒领取一个索引任务，通过 CAS 更新为 RUNNING 并分配 runId。事务快照生成指定修订的内容：在线型正文或上传型唯一原文件。历史混合数据保持兼容。
3. Python 只下载配置的 MINIO_ENDPOINT 同源签名链接，不跟随重定向；限制流式下载大小，并核验文件大小与 SHA-256。
4. TXT/MD 支持 UTF-8 BOM 和 GB18030；PDF 保留页码，拒绝加密、损坏或无可提取文字的文件；DOCX 顺序读取段落与表格，限制压缩包条目和解压后总大小。
5. SentenceSplitter 使用显式中英文分句器，不依赖运行时 NLTK 语料；以 400 token 分块、64 token 重叠，分块带 book_id/source/file_id/page/chunk_no。正文作为独立来源 Book 正文；资料中的指令仅为内容。
6. 稳定分块 ID 包含 Book、来源、序号和嵌入文本。未变化的分块复用向量，新增分块按最多 10 条一批调用嵌入服务。
7. 嵌入请求在数据库事务外执行。最终切换版本在 PostgreSQL 事务内取得每 Book advisory lock，再检查全局版本与删除标记，写入当前分块并删除不在清单中的分块。
8. Java 只接受匹配 RUNNING/runId 的结果，且仅更新同 revision 的 Book。旧结果标记 SUPERSEDED。失败展示原因，可手动重新索引；15 分钟运行超时会失败。

## 检索与生成

问答必须满足 READY 且 indexed_revision=revision；编辑未保存时页面禁止提问。Python 同时验证全局状态与当前模型空间的版本，所有召回严格过滤 Book 和 revision。查询先在短只读事务验证就绪状态，退出事务后等待查询嵌入；再开启 REPEATABLE READ READ ONLY 事务，以同一快照复核状态、读取向量与关键词候选。远程或本地模型等待不持有 Book search 的事务与锁。向量召回最多 30 条，并结合中文词/双字关键词召回；默认权重为余弦相似度 0.75、关键词覆盖 0.25，相关阈值可通过 RAG_MIN_SIMILARITY 配置。

模型仅根据筛选片段回答，返回有效数字引用、来源名、页码、分块号和原文。没有匹配片段不调用聊天模型。非法引用编号不展示为正常回答。Java 回答后再核验 Book revision，期间内容变化要求重新提问。history 最多六条，角色仅 user/assistant、单条最多 4000 字；检索补充先前用户问题以支持追问，生成优先当前原文证据。

问答采用统一的结论/论据契约：模型返回 conclusion/evidence JSON 字符串字段，服务端验证字段、非空内容与有效证据引用，再组合为两段 Markdown。格式或编号失败允许一次格式重试，仍失败明确返回不可核验错误。结论只依据本轮当前范围；论据由有效引用编号组合为“出处：[1]、[3]”，丢弃模型生成的解释和摘录，并按文件/页码去重；前台只显示来源名称与页码。无片段走确定性的两段依据不足响应，不调用模型、不制造来源、不把局部检索失败扩大成全库缺失。该约束不改变写作工作流。

带 bookId 的写作任务要求 Book 已就绪，每阶段检索其最新就绪版本。内部 /internal/write 的 book_id/book_revision 必须成对传入；单边缺失返回 422，索引版本冲突返回 409。人工确认最终阶段后创建新 Book，再入队向量化；源 Book 与附件保留。新 Book 不复制源附件，保留生成正文；任务记录源知识库关系。

## 笔记助手与 Agent（阶段 4）

Book 笔记操作由 Java `AssistantService` 鉴权、读取当前修订并准备受限检索上下文；Python `/internal/assistant` 只负责结构化生成。整理与润色结果返回预览，作者应用时必须提交 `expectedRevision`，沿用 Book 修订历史与索引队列。文件型 Book 允许整理元数据，不允许覆盖原文件内容。重复/冲突发现必须带来自其他可访问 Book 的来源编号；资料不足时不推断。

Agent 偏好保存在 `assistant_memory`，计划与步骤分别保存在 `assistant_plan` 和 `assistant_plan_step`，均以当前 user ID 隔离。建计划前限定为用户选择且 READY 的 Book，并将 ID、标题、revision 快照持久保存。计划可由模型最多提出 6 步，也可由用户自定义 1–6 步；Java 校验 search/summarize/compare/draft/proofread 白名单和步骤依赖。用户逐步触发执行且必须按顺序。只有 search 访问 RAG；其他步骤使用此前累积的来源证据与生成稿。保存后可编辑步骤、插入、移动和移除；变更会重置受影响步骤及后续结果，允许保留前序结果后重新执行。用户也可从任意步骤重置下游结果；检测到旧的“无出处”回答与前置命中来源冲突时，工作台会提供保留来源并重跑后续的入口。每步开始和完成时重新读取权限及 revision 快照，结果存为 JSON，失败状态可重试。proofread 读取最近的 draft 及来源，旧版 compare 翻译计划也兼容转入校对；缺少证据时明确阻止生成，不再把处理指令单独作为检索问题。执行只访问知识检索服务，不开放模型任意函数调用、数据库或存储访问。

合并与起草流程先检索授权范围内的证据，再生成带来源的预览；新草稿需通过显式创建请求，并重新核对来源访问范围。结果是新的私有 Book，原文不变且不自动发布。长期建议目前根据个人 Book 的简介、分类/标签和索引状态计算。

## 学习辅助 Agent（阶段 6）

`LearningService` 先对当前用户选择的 1–50 本 READY Book 执行混合检索，再将目标、自评起点、计划参数和真实片段交给内部 `/internal/assistant` 的 `learning_roadmap` 操作。模型须返回限定周数与每周任务数的 JSON；Java 再校验任务数量、文本长度和来源编号，只保存映射到本轮真实检索结果的出处。计划生成期间若权限、索引或 Book revision 改变则返回 409。学习周期最多 8 周、每周最多 7 次、每次 10–180 分钟。

MySQL `learning_plan` / `learning_session` 按用户和计划外键隔离保存路线、日期、来源、状态、信心分、反思及报告。`LearningSchema` 用 `CREATE TABLE IF NOT EXISTS` 幂等补齐已有安装，不删除数据库内容。任务可改为完成、需要复习、跳过或恢复待学习；进度和低信心薄弱点由保存的任务记录计算。报告至少需要一次完成/待复习记录，提示模型只基于自评、反思和计划来源归纳，并将水平标为估计。打卡变更会清空旧报告；再次生成前还需复核计划 Book 的访问权限与 revision。学习结果不写回 Book，也不自动推送。

## 删除与恢复

删除 Book 先软删除业务记录，禁止详情、下载与问答，再入队 DELETE。文件每 30 秒清理，失败保留 purged=0 供后续重试；向量 DELETE 失败 60 秒后自动重试。pgvector 保存共享删除墓碑，并清理该 Book 在应用所有模型命名空间中的分块，防止迟到的旧任务恢复已删除内容。清理是异步的，删除业务响应不代表底层存储已即时清空。

## 模型和部署

聊天首选 https://dashscope.aliyuncs.com/compatible-mode/v1 的 qwen3.8-flash，关闭 thinking。密钥读取 Windows 用户环境变量 DASHSCOPE_API_KEY，Start-AI.ps1 用 WSLENV 传入 Python；不进入命令行或跟踪文件。备用 DeepSeek/Qwen/GLM/Ollama 渠道保留，每渠道最多两次尝试。

嵌入默认 remote：text-embedding-v4、1024维、相同 DashScope 密钥。local 可选 FastEmbed BAAI/bge-small-zh-v1.5、512维、CPU，首次下载模型。EmbeddingSpace 从 Provider 实际生效配置提取 base_url/model/dimensions，Book 与内部快照检索共用身份计算；保留原 Book 的 SHA-256(base_url+model+dimensions) 前 12 位哈希，既有向量命名空间不迁移。不同向量空间隔离，凭据不参与身份。Setup-RAG.ps1 复用已有 pgvector 容器创建专用数据库、账号和扩展，DSN 写入本地忽略文件。
