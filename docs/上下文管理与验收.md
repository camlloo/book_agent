## 对话摘要规则

1. 原消息保存在 `knowledge_message`，摘要是可重建的派生数据，不替代原记录。
2. 默认保留最近 8 条成功且未隐藏的消息。更早的待压缩消息累计至少 4 条时，合并此前摘要与新增用户原话；通常从第 7 次提问开始生成摘要，之后约每两轮增量更新。
3. 摘要包含 `focus`、`constraints`、`entities`、`decisions` 和 `open_questions`。压缩输入仅提取用户原话，不把助手的历史知识结论写成事实记忆。
4. 摘要和相关旧问题仅帮助理解意图、指代及表达要求。知识事实仍须依赖本轮有权且当前就绪的检索片段，回答继续采用“结论 + 简短论据出处”。
5. 生成摘要、检索回答前后复核身份、知识范围和历史可见性。仅在答案提交事务中保存新摘要；会话被删除或权限变化时不提交迟到结果。
6. 每段对话独立管理摘要。`assistant_memory` 中由用户维护的长期偏好仍独立保存；本次没有把某段对话自动转成跨会话的永久偏好，也没有把聊天记录写入 Book 向量库。

## 预算配置与边界

默认主渠道仍为 DashScope `qwen3.8-flash`。在 `ai/config.yaml` 或本机 `AI_CONFIG` 指定的配置中，可按渠道设置：

```yaml
context_window: 32768
input_token_budget: 24000
token_safety_ratio: 1.15
```

输入上限同时受 `context_window - 输出预留 - 1024` 约束。任务输出预留分别为：检索问题改写 500、历史摘要 1800、提纲 4000、问答 6000、扩写 / 润色 8000；小窗口还会缩减输出预留。Ollama 默认使用保守的 4096 应用窗口；其他备用渠道应按实际服务能力配置。

Token 使用 cl100k_base 进行**跨模型估算**，不是 Qwen 的精确分词；15% 余量不代表服务商实际 Token 数完全一致。实际 usage 有返回才记录，缺失值不按零统计。当前提供日志与问答响应中的 context 诊断字段，未新增费用仪表盘。

长文分析选段是有损操作，界面中的改写结果仍需作者审核。长文润色 / 校对按完整输入分段，最多 64 段；单个围栏代码块不能超过单段预算，超限明确要求按函数或文件拆分。支持反引号、波浪线及外层较长围栏。请求仍受现有模型 / 工作流超时限制；分段结果在本次请求中组织，没有新增逐段后台恢复任务。

## 验收步骤

| 验收 | 编号 | 操作 | 预期结果 |
|---|---|---|---|
| [ ] | C01 | 新建对话，第一轮给出项目名、语言和禁止表格等约束，连续问答 7–9 轮 | 较早约束进入摘要；后续会复用并增量更新摘要 |
| [ ] | C02 | 刷新页面、从“最近”重新打开该对话，或重启后继续 | 原消息保持，摘要缓存可继续读取；新对话不混用旧摘要 |
| [ ] | C03 | 压缩服务暂时失败后继续提问 | 本轮使用有效旧记忆、近期消息和相关旧问题降级处理；诊断标记 summaryFallback |
| [ ] | C04 | 撤销某个引用 Book 的访问权限或修改其修订 | 原回答按权限隐藏；旧摘要指纹失效；处理中的权限变化阻止交付迟到答案 |
| [ ] | C05 | 执行检索 → 总结 → 起草 → 校对计划 | 后续步骤同时获得各前序步骤记忆和当前有效证据；不重复把处理说明当作检索问题 |
| [ ] | C06 | 用超过 7000 估算 Token 的长文润色 / 校对，末尾放入可识别内容 | 所有片段依次处理；末尾不会因固定字符截断而消失；完整结果仍需作者审核 |
| [ ] | C07 | 输入超长单一代码块，或模拟模型输出达到长度上限 | 明确失败或要求分段，不把不完整正文当作成功结果 |
| [ ] | C08 | 查看服务日志与本轮问答响应 | 预算 / usage 和 context 诊断可用；日志不包含密钥、完整用户问题或正文 |
